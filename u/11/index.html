多轮对话：把说过的话带回来

记忆不是模型的能力，是外面替它记的。

先看一眼

“记得住”是外面替它记的

到底怎么回事

机制与边界

补上一节的洞，办法很粗暴：每次提问，都把前面的对话一起发过去。

它到底发生了什么

你问第三句的时候，程序实际发过去的是三段内容，而不是一句：

[
  { "role": "user",      "content": "我叫小明。" },
  { "role": "assistant", "content": "好的，小明。" },
  { "role": "user",      "content": "我叫什么？" }
]
记住这个结论，它会改变你很多用法上的判断：“它记住了”其实是“它又被喂了一遍”。所以每多聊一轮，发过去的内容就长一截，花的钱也多一截。

这个做法带来了两个新麻烦

对你有什么用

知道这件事之后，你会自然养成一个习惯：关键信息在前几轮就说清楚，别指望聊到一大半再补。 因为越靠后的内容，越可能被压缩掉（第 12 节会讲）。

你自己跑一遍

现场验证

同一个问题问两次，区别只在第二次带上了前文。

预期 · 它不知道。因为它这次只收到了这一句话。

这次要发出去的内容
user我叫什么？

这一页的演示走的是服务商公开的 chat/completions 接口，这样你的浏览器才能直接发出去。DSH 自己内部用的是 Anthropic Messages 格式（/anthropic/v1/messages），两者字段不完全一样——这里看到的是「同一个模型、另一种调用姿势」。

请求从你的浏览器直接发往 api.deepseek.com，不经过任何中间服务器。 max_tokens = 16000。

下面这段 Python 一次跑出两种结果：先用单句问，再把历史一起发。差别在你自己眼前发生， 而不是听我说。

真 Python · 在你的浏览器里跑首次约需下载 10MB 运行环境

下面这段是真正的 Python 代码，不是伪代码。它在你的浏览器里用 Pyodide 执行，`requests` 请求直接从浏览器发往 DeepSeek，不经过任何中间服务器。

同一个函数、同一个问题，唯一区别是第二次多带了前两轮。跑完对比两行输出。

import requests


def ask(messages):
    resp = requests.post(
        "https://api.deepseek.com/chat/completions",
        headers={"Authorization": "Bearer " + DSH_API_KEY},
        json={"model": "deepseek-flash", "max_tokens": 4000, "messages": messages},
    )
    return resp.json()["choices"][0]["message"]["content"]


# ① 只发最后一句
print("① 只发最后一句：")
print("   ", ask([{"role": "user", "content": "我叫什么？"}]))

# ② 把前面的对话一起发过去
history = [
    {"role": "user", "content": "我叫小明。"},
    {"role": "assistant", "content": "好的，小明。"},
    {"role": "user", "content": "我叫什么？"},
]
print("② 带上历史：")
print("   ", ask(history))

print()
print("第二行多带了两条消息，它就从“不知道”变成了“知道”。")
