到底怎么回事

机制与边界

第 1 节我说过它“写完就忘”。这一节我们把这件事看透， 因为后面所有关于记忆的功能，都是在补这一个洞。

真相：每一次调用都是一次性的

一个好用的类比

把它想成一家公司的轮班咨询台：每一通电话都换一个刚上班的顾问。 他能力很强，但桌上什么文件都没有。 你上一通电话跟另一位顾问说过的事，他完全不知道—— 除非你在这一通电话里再讲一遍。

这不是缺陷，是设计如此。一次性调用意味着便宜、可控、可以无限并行。 需要“记忆”的时候，由外面那层系统负责把该带的信息带上—— 这就是下一节要讲的事。

这个概念的名字

在 DSH 的界面里，你看到的一段连续对话叫一个会话。 会话之所以能连着聊，完全是外面在替你保管并重新发送历史。 理解了这一点，你以后遇到“它怎么突然忘了”就不会困惑了。

下面这段是真正的 Python。它把「单次调用」的请求体原样写了出来——你可以清楚看到， 发过去的东西里只有一句话，没有任何历史。

真 Python · 在你的浏览器里跑首次约需下载 10MB 运行环境

下面这段是真正的 Python 代码，不是伪代码。它在你的浏览器里用 Pyodide 执行，`requests` 请求直接从浏览器发往 DeepSeek，不经过任何中间服务器。

这段代码只发一句话。注意 messages 里只有一个元素——这就是“单次调用”的字面意思。

import requests

# 一次「单次调用」：只发一句话，其它什么都不带
resp = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": "Bearer " + DSH_API_KEY},
    json={
        "model": "deepseek-flash",
        "max_tokens": 4000,
        "messages": [{"role": "user", "content": "我叫什么？"}],
    },
)

print("HTTP 状态码：", resp.status_code)
print("发过去的内容：只有「我叫什么？」这一句")
print("它的回答：", resp.json()["choices"][0]["message"]["content"])
