机制与边界

这一节是全书唯一一节不需要从头读的。它是查的： 第一张表是看不懂的词，第二张表是“我想做 X，该怎么说”。 现在读一遍混个眼熟就够，以后卡住了再回来翻。

用法上只有一个建议：别背。你背不下来的词，它自己解释得比谁都好。这一页真正的价值是让你知道 “原来这件事有个名字”，有了名字你才问得出口。

术语表：二十个词，人话版

解释的顺序大致是按你遇到它们的先后排的。看不懂某个解释里引用到的另一个词， 往下翻两行就是。

模型（大模型）

只负责“想”的那一半：给它文字，它接着往下写。它没有眼睛、没有手，碰不到你的文件。

会话

一段独立的对话。新开一个会话，等于跟一个什么都不记得的它从头开始。

上下文

这次真正递到它面前的全部内容：你的话、之前的对话、它的说明书、你让它读的文件。它不是记忆，是桌上摊开的纸。

上下文窗口

那张桌子的大小。一次最多摊这么多纸，摊不下了就得先收走一些（见“压缩”）。

token

计费和长度的最小单位。中文字数和一个 token 不是一对一，所以别拿它精算账单。

思考 token

推理模型答题前先在心里打的草稿。它算钱，但**不计进单独的桶**——用量统计里它并进「输出」那一项，只是不一定显示给你看。

推理模型

先想再答的模型。同一句话它比普通模型花得多，换来的是复杂问题上更少跑偏。

工具调用

它说“我要去读那个文件”，然后真的去读了。这是真正动手的环节，也是它能改你电脑的原因。

审批

它准备动手时停下来问你一句。不是弹窗找麻烦，是它要碰你的东西了。

沙箱

给它划的活动范围：只读、只能改工作区、完全不限制这几档。范围越小，闯祸的代价越小。

工作区

它默认可以活动的那个文件夹，默认就是你的启动目录。图形界面里也可以另外登记几个工作区。

技能

把“这类活该怎么做”写成一份说明。以后遇到同类任务它照着做，你不用重讲一遍。

插件

给它加一件新能力的外部零件。装之前先问一句：这东西是谁写的、可信吗。

profile

一套配置的组合。同一个 DSH，用不同 profile 启动，出来的是网页界面、一次性的活，还是给程序调用的接口。

子智能体

它把一块独立的小活派给另一个自己，回来只带结论、不带过程。省的是你眼前的上下文，不一定是钱。

工作流（workflow）

让模型写一小段调度脚本，把十几块互不相干的小活同时派出去，再汇总结果。活少的时候不值得动用。

幻觉

它不知道，却顺着话头编，语气还特别自信。这不是故障，是它的工作原理。

压缩

上下文快满了，把前面的历史缩成摘要，腾出地方继续聊。缩掉的那部分就真的没了。

检索（RAG）

一个通用概念：需要的时候把相关资料先找出来，再连同问题一起交给模型。注意 DSH 本身走的不是这条路——它直接用 read / glob / grep 去读你的文件，没有向量检索那一套。别把它当成 DSH 的功能。

自动化任务（定时任务）

到点往某个会话里发一条消息的闹钟。发完它就不管了，活还是那个会话里的它来干。这是可选能力，随发行版默认禁用。

这里有一条实测出来的换算，可以直接拿来粗估字数：1 个中文字符 ≈ 0.6 个 token，反过来约 1.67 个字 / token。

怎么测的：用同一句话重复 1、5、10 次发过去，读返回的输入 token 数， 三个点拟合出一条直线，残差为 0。 另外每条消息本身还有约 30 token 的固定格式开销。 注意这是这个模型、这段文字风格下测出来的—— 换成英文、代码或大量数字，比例会不一样。

待核实
profile、插件这些词在你那个版本的界面上到底叫什么、藏在哪个菜单里， 我是按 DSH 的实现文档写的，没在你的界面上逐个点过。 词对不上不要紧，把界面截图发给 DSH 问一句「这个对应文档里说的哪个东西」，它能自己认。

速查表：我想做 X，该怎么说

左边是你脑子里的话，右边是可以直接复制过去的说法。 这张表里没有一句是客套话——每一句都是在替它消除一个歧义。

我想做的事这样说
让它先搞清楚情况再动手“先只读，不要改任何文件。看完告诉我你打算怎么做。”
让它交一个能直接打开的文件“结果存成 Excel，放到 D:\汇总，文件名用 2026-03-工作记录。”
让它批量改文件名“把 D:\发票 里的 PDF 按月份重命名。先只给我一张改名前后的对照表，我确认了你再改。”
它交的活不对“停一下。你错在 X，正确的标准是 Y，从出错那一步重做，别动其它文件。”
同一个要求每次都得说一遍“把这套做法记下来，以后遇到同类任务直接按这个来。”
想让它每天早上自己做“我想让这件事每天早上八点自动做一次。在这个会话里帮我建一个每天的定时任务，做完把结果放到 D:\汇总。”
活太大，一次做不完“这个任务分几步做，每做完一步停下来给我看结果，我说继续再往下。”
一堆互不相干的小活“这些文件互相没关系，可以同时处理，用工作流一次跑完。”
怀疑它在编“你这句话的依据是什么？不确定就直接说不确定，不要猜。”
它越改越多、收不住手“停。只改我指定的那一个文件，其它文件一个字都不许动。”
想知道这次花了多少直接问：“这次大概用了多少量？”——本站在演示框下面也会显示每次跑完的 token 数。
想把改动退回去动手前：“先复制一份到 D:\备份，再动原件。”出事时：“把改动全部撤销，恢复成 D:\备份 里的版本。”
看不懂它说的某个词“用完全不懂技术的人能听懂的话解释「这个词」，举一个生活里的例子。”
想让它自己检查一遍“交给我之前自己检查一遍：有没有漏项、有没有编造，把不确定的地方单独列出来。”
它太啰嗦“结论先行，三句话以内，不要复述我的要求。”
想知道它到底改了什么“把这次动过的文件列出来，每个文件改了什么，一句话一条。”

最后，如果只能记一句话

这本书里所有的话术技巧，其实都在做同一件事：把“你脑子里知道、但没说出口”的部分，说出来。你觉得文件当然应该按月份分、你觉得“整理”就是别删东西、 你觉得日期当然要写成 2026-03-05—— 这些对你是常识，对它是一片空白。你说出来的部分，它才做得到。

剩下那一大堆没说的部分，就用这一节的两张表兜着。 查不到，就直接问它。这是全书里唯一一个你能一直用下去的办法。

现场验证

把一段满是行话的话丢给它，让它翻成人话。

只存本地，不上传

预期 · 它会把这句黑话拆成：派几个帮手同时干、别让桌上堆太多纸、动手前要问我一句、别让它跑出划定的范围。术语表里那些词，落到地上就是这么点事。

这次要发出去的内容
user请把下面这段话翻译成完全不懂技术的人能听懂的话，并指出其中哪些词是行话、各自的人话意思是什么：「用子智能体并行跑一个 workflow，注意上下文压缩和审批门，别忘了沙箱。」
