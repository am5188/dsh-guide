机制与边界

上一节为止，你都是在派活：说一句，它做一件。这一节讲的是怎么从“每次都说一遍”，走到“它自己按时做”。 中间其实只有三样东西，各自治一个病：

你的处境于是加上了在 DSH 里叫
这套做法我讲过一遍了，不想再讲把一整套步骤固定下来，下次照着走工作流
这事每天都得做，我老是忘到点自动开始，不用人先想起来定时任务

最容易误会的一件事：定时任务本身不干活

定时任务是闹钟，不是工人。闹钟响得再准，也不能替你起床。所以“它自己按时做”这件事真正的难点， 从来不是定时间，而是你有没有把该交代的交代清楚。

哪些事能交出去，哪些事交出去就是给自己找麻烦

适合自动化
  • 重复的：今天这么做，下个月还是这么做
  • 规则说得清的：什么文件、放哪里、叫什么名字
  • 结果有固定去处的：存到某个文件夹、发到某个地方
  • 你一眼能验收的：打开看一眼就知道对不对
  • 用的是副本的：原件还好好躺在那儿
别自动化，先手动
  • 每次情况都不一样的：得临场看一眼才知道怎么办
  • 要跟别人确认的：中间得有人点头
  • 好坏你自己都说不出标准的：写得“好不好”全凭感觉
  • 要动唯一一份原件的：错了没有第二条路
  • 做错了没人会发现的：安安静静错上一个月

动手之前，必须满足的三个条件

一条不满足，自动化只是把你的错误从「一次」变成「每天一次」。

条件什么算满足不满足会怎样
任务稳定同一件事手动做十次，步骤基本一样，没有每次都变的花样它会把偶发的例外当成常态，天天错，而且错得很稳定
结果可验证你能用一句话说清“做成什么样算对”它交回来的东西对不对，你自己也拿不准，只能凭感觉收下
失败有通知它没跑成、或者跑出来的东西不对，当天就有人知道坏了没人知道，等你发现的时候已经错了很多次

“先手动跑顺十次再自动化”

第十次还出现的例外

这才是真正需要写进规则里的东西。

只出现过一次的

多半是那次你自己手滑了，不必写成规则。

每做一次，顺手记一句“我刚才凭什么这么判断”。 这些判断就是自动化时必须提前写进交代里的部分。 比如“同一个月的发票放同一个文件夹”——你觉得这是常识，它不知道你的常识。

DSH 里这些东西长什么样

定时任务在 DSH 里叫自动化任务。下面这些是从 DSH 自己的实现文档里读到的：

在哪找
有一个跨会话的「自动化任务」页面；每个会话的右侧栏里也有一个任务页签。
到点之后
提醒作为一条消息回到当初创建它的那个会话，由那个会话接着干。所以它是「绑定会话」的，不是凭空变出一个新助手。注意回执只表示消息投进了收件箱，不代表模型已经执行。
能改什么
名字、指令、运行时间；也能看这条任务过去几次的运行记录。
时间怎么定
不用背语法，是选的：每周 / 周一至周五 / 每天 / 每 N 小时 / 每 N 分钟 / 每 N 秒 / 仅一次，另有一条自定义可以填 cron 表达式。
两个限制
重复间隔最短 60 秒（一次性延迟没有这个下限）；时区只有「每天 / 每周 / 自定义 cron」能单独指定，固定间隔和一次性不认时区。
怎么创建
创建动作是在会话里完成的——在自动化任务页点「新建」会打开一个新会话，由你在那个会话里让它建任务。
默认没开
这个功能随发行版默认禁用，要在插件管理页里启用带闹钟图标的「自动化任务」。
界面上找不到「自动化任务」是正常的——它随发行版默认禁用。 先去插件管理页的「官方」分组里启用（包名形如@deepseek-ai/dsh-experimental-schedule-bundle），别以为自己的版本坏了。 上面这些是读 DSH 实现文档得到的，我没在你的界面上一一核对过； 桌面版与网页版是否完全一致，我也没有两边都点过。

工作流：只给「十几块互不相干的小活」用

十几块，谁都不等谁

值得动用工作流：让它写一小段调度脚本，把这些小活同时派给好几个自己，跑完汇总成一份结果。

只有一两件

普通的子智能体就够了。为两件事开一场会，纯属浪费。

你不需要自己写那段脚本。派活的时候说清楚“这些文件互不相关，可以同时处理”，剩下的它自己决定。 工作流是它的工具，不是你要学的新语言。

自定义配置：把“我这边的情况”提前交出去

从「随手」到「正式」有四层：

1会话自己的记忆最随手，也最不牢靠（第 11、12 节讲过它会忘）
2规矩文件每次自动带上；普通人最该知道的一层，下面细说
3设置页管着模型、联网这些开关
4profile 与插件最正式，属于进阶

最该知道的是那份规矩文件：干活前 DSH 会读 DSH 数据目录里的AGENTS.md，再读项目目录里的同名文件，越靠近当前目录越优先。 没有就自己新建一个，几条短句足够：

一份规矩文件可以写什么
  • 我平时把文件放在哪个盘、哪个文件夹
  • 交东西给我时，默认要什么格式（Word、Excel、还是 Markdown）
  • 日期、金额、人名的写法，统一成什么样
  • 不许做的事：别删原件、别动这个文件夹以外的东西
  • 说话的方式：结论先行，别复述我的要求
待核实
先纠正一处常见误解：本地覆盖不是「同名目录下任意 *.local.md」， 而是只有两个固定文件名—— AGENTS.local.md 和 CLAUDE.local.md； 而且只有项目那一层有本地覆盖，全局那份没有。

其余几条读自 DSH 的实现文档：全局那份在 DSH 数据目录 （默认 ~/.dsh， 可用 $DSH_HOME 改）， 项目根靠 .git 定位； 加载顺序是「项目根 → 当前工作目录」，越具体越优先； 内容按**内容**去重（把 AGENTS.md 复制成 CLAUDE.md 不会重复加载）； 整份渲染后的上限是 65,536 字节，超了会先整份丢掉较宽泛的那份、 再截断最具体的那份，并给你一条通知说明省略了哪个路径。

我没在界面上逐条点过，也没验证桌面版与命令行版行为完全一致。 你先写三行试一次，看它是否照做——这比信我要快。
最后留一句可以贴在墙上的话：自动化放大的不是你的能力，是你原本的做法。做法本身有毛病，自动化只会让它每天准时发作一次。
你自己跑一遍

现场验证

让模型帮你把「这件事该不该自动化」想清楚。

只存本地，不上传

预期 · 它通常会把“收集昨天改过的文件、按固定格式汇总”划到可自动化一边，把“判断哪些事值得写进去”划到另一边。最后那句任务描述，就是你要提前交代的全部内容。

这次要发出去的内容
user我每天要做这件事：整理前一天的工作记录，写成一段总结。我想改成每天早上 8 点由 AI 自动做。请判断：这件事的哪些部分适合自动化，哪些部分不适合？不适合的部分请说明原因。最后给我一句可以直接交给 AI 助手执行的任务描述。不要提具体价格。

这一页的演示走的是服务商公开的 chat/completions 接口，这样你的浏览器才能直接发出去。DSH 自己内部用的是 Anthropic Messages 格式（/anthropic/v1/messages），两者字段不完全一样——这里看到的是「同一个模型、另一种调用姿势」。

请求从你的浏览器直接发往 api.deepseek.com，不经过任何中间服务器。 max_tokens = 16000。

$ dsh --profile headless "把 D:\记录 里昨天的文件整理成一段总结，存到 D:\记录\总结.md"
跑完你应该看到

它跑完只打印最终答案，然后退出。这就是所有自动化的最小零件：一条跑完就退出的命令。

运行命令时所在的目录会成为它默认的工作目录，所以先切到你想让它动手的那个目录，再运行。
