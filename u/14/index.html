它动不了手：function calling

模型不会读文件，但它可以决定“该去读哪个文件”。

先看一眼

模型只负责“说要调什么”

到底怎么回事

机制与边界

前三节解决的是「它知道什么」。这一节开始处理「它能做什么」。

模型自己什么都没执行

这个循环叫工具调用。第 3 节那张「一句话变成一堆动作」的图，说的就是它。

为什么这是个突破

它把模型从「只会说」变成了「会指挥」。 第 1 节那道过不去的墙就是这样绕过去的——不是模型越过了墙，是墙外有人替它递东西。

一个重要的推论

能执行什么、允许执行什么，完全由外面决定，不由模型决定。 这就是权限和沙箱为什么重要：模型可以提任何请求，答不答应是系统和你说了算。

你自己跑一遍

现场验证

先看它怎么「请求调用工具」，再看真正的两次往返。

只存本地，不上传

预期 · 它会输出一段 JSON，然后承认自己并没有真的读文件。这段 JSON 就是“工具调用”的真身——一串文字而已，执行者是别人。

这次要发出去的内容
user假设你有一个名为 read_file 的工具，它接受一个参数 path。 现在请以 JSON 格式输出你这样一次工具调用的请求，格式为： {"tool": "工具名", "arguments": {参数}} 任务：读取 D:\发票\三月.pdf 并提取其中的金额。 输出 JSON 之后，用一句话说明：为什么你输出这段 JSON 之后，自己并不能真的读到那个文件。

这一页的演示走的是服务商公开的 chat/completions 接口，这样你的浏览器才能直接发出去。DSH 自己内部用的是 Anthropic Messages 格式（/anthropic/v1/messages），两者字段不完全一样——这里看到的是「同一个模型、另一种调用姿势」。

请求从你的浏览器直接发往 api.deepseek.com，不经过任何中间服务器。 max_tokens = 16000。

上面那次只是一次调用。 真正的工具调用是一来一回两次：模型先说要调什么，外面执行完，再把结果发回去，模型才给最终答案。 下面这个会把两次请求的完整 JSON 都摊开给你看。

完整工具调用回路 · 真调用工具本身是本地模拟的

和上面的面板不同，这里会连续发两次请求： 第一次模型要工具，本地执行后，第二次把结果发回去。 这一来一回，就是「智能体」这个词的全部含义。

注意三件事：① 模型自己决定要调哪个工具、参数填什么；② 它输出的只是一段 JSON，真正读目录的是外面；③ 它拿到结果以后，还要再被调用一次才给出最终答案。这个「一来一回」，就是智能体循环的最小形态。

下面这段 Python 让模型把「请求调用工具」写出来， 然后你亲眼看一遍：响应里只有文字，没有任何东西被执行。这就是这一节最核心的一句话。

真 Python · 在你的浏览器里跑首次约需下载 10MB 运行环境

下面这段是真正的 Python 代码，不是伪代码。它在你的浏览器里用 Pyodide 执行，`requests` 请求直接从浏览器发往 DeepSeek，不经过任何中间服务器。

这段代码把模型的输出打印出来。它看起来像一个“动作”，但本质只是一段字符串——浏览器里什么也没发生。

import requests

resp = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": "Bearer " + DSH_API_KEY},
    json={
        "model": "deepseek-flash",
        "max_tokens": 4000,
        "messages": [{
            "role": "user",
            "content": (
                "我想读一个文件。请用 JSON 说明你会怎样请求调用一个叫 "
                "read_file 的工具，只输出 JSON，不要其它文字。"
            ),
        }],
    },
)

data = resp.json()
print("HTTP 状态码：", resp.status_code)
print()
print("模型返回的全部内容：")
print(data["choices"][0]["message"]["content"])
print()
print("这段代码跑完了。你的文件系统没有任何变化——")
print("因为真正去读文件的，是模型外面那层系统，而不是模型自己。")
